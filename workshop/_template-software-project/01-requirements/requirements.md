# Requirements

What the system must do. Method: `workshop/skills/testable-requirements/`.

Two rules for the two columns:

- **Requirement** = plain domain language: WHAT the system does, for
  WHOM - one sentence a stakeholder can repeat in their own words
  without seeing the test. No metrics, thresholds or fixtures here.
- **Acceptance criterion** = all the measurement machinery: what is
  measured, under which conditions, where the pass/fail line sits.

| ID | Requirement | Acceptance criterion | Priority |
|----|-------------|---------------------|----------|
| REQ-001 | <plain-language statement - what the system does, for whom> | <what is measured, under which conditions, where the line is> | MUST |
